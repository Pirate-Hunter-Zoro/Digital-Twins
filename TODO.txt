- [ ] VITALS STEP 1 — REFACTOR FEATURE-side vitals handling to a
      per-classifier legal-arm sweep over three arms: DROP,
      INDICATOR_ONLY, and NAN. No imputation. The packaging diagnostic
      in notebooks/cohort_investigation.ipynb shows P(all 3 missing
      | ≥1 missing) = 90.3% across the cohort, so vitals are missing
      in packages and within-vital multivariate interpolation (MICE,
      KNN) has no within-vital signal to chain — these imputers
      degenerate to predicting BMI/BP from non-vital regressors,
      which only reproduces the engagement-disparity signal already
      encoded by the missingness flag itself. Median imputation is
      also redundant under an indicator-bearing matrix: the filled
      value is mathematically absorbed by the indicator coefficient
      under LR and largely absorbed under tree splits when the tree
      branches on the indicator first, so the placeholder adds no
      scientific signal while injecting cohort-median-flavored
      numbers into cells where the truth is "unknown". Current
      implementation iterates three global strategies (DROP /
      INDICATOR / ASYMMETRIC) across all four classifiers under a
      `ClassifierFamily` coordination shim with an ASYMMETRIC
      dual-load. Replace with a per-classifier legal-arm matrix
      where each classifier sweeps only the strategies it can
      actually run, with no imputer anywhere in the pipeline.

      Three arms:
        * DROP — strip VITAL_COLUMNS at load_data_set time. Vital
          info is genuinely absent from the matrix. All four
          classifiers can run.
        * INDICATOR_ONLY — strip the vital VALUES (same matrix
          shape as DROP for the value columns) and append three
          pre-computed boolean indicator columns showing which
          patients were missing each vital. No fabricated numbers
          anywhere. All four classifiers can run.
        * NAN — passthrough; vitals retained with NaN-bearing cells,
          no imputer. Only XGBoost has native NaN-aware splits; LR /
          RF / GB raise on NaN.

      Lineup change: swap `HistGradientBoostingClassifier` back to
      plain `GradientBoostingClassifier`. HistGB was adopted to feed
      NaN-bearing matrices to the tree branch under the prior
      INDICATOR / ASYMMETRIC design; with the new design only XGBoost
      runs the NaN arm, so the HistGB-required path disappears. Plain
      GB also restores native `feature_importances_`, eliminating the
      AttributeError that currently kills feature_importance.py
      mid-run (slurm_jobs/quick_runs/logs/analysis_only_err.txt:1184).

      Hyperparameter grid revert for `gradient_boosting`
      (classical_ml.py:174-179): drop the three HistGB-only keys
      `model__max_iter`, `model__max_leaf_nodes`,
      `model__l2_regularization`; keep `model__learning_rate`
      ([0.01, 0.1, 0.3]); add `model__n_estimators` ([300]),
      `model__max_depth` ([3, 5, 8]), and `model__min_samples_split`
