- [ ] FEATURE-side vitals-handling sensitivity analysis. The three
      vital columns currently emitted by feature_vector.py
      (`bmi`, `bp_sys`, `bp_dias`) sit at 63-69% missingness across
      the n=9725 cohort, with TRD-positive patients an additional
      8-10 percentage points more likely to be missing every vital
      than TRD-negative patients (diagnostic + cross-tab live in
      notebooks/cohort_investigation.ipynb). Median imputation at
      classical_ml.py:84 was therefore squashing the engagement-
      disparity signal onto the cohort median, and the LR was learning
      "patient with cohort-median BMI = TRD proxy" — producing the
      literature-incoherent protective-BMI red bar across all four
      FEATURE feature_importance PNGs. Rather than commit to a single
      handling strategy on first-principles grounds, the FEATURE
      pipeline iterates a three-arm sensitivity comparison; the
      primary arm is reported in the manuscript and the secondary
      two are reported as sensitivity analyses.
      Arms:
        * DROP — strip `bmi` / `bp_sys` / `bp_dias` from the FEATURE
          matrix at `load_data_set` time. All four classifiers see
          the same vital-stripped columns. SimpleImputer is a no-op
          on the resulting numeric block.
        * INDICATOR — vitals retained. LR's numeric branch uses
          `SimpleImputer(strategy='median', add_indicator=True)`,
          which appends a `MissingIndicator` column per imputed
          feature (three new boolean columns:
          `missingindicator_bmi` / `_bp_sys` / `_bp_dias`). Tree
          models drop the imputer entirely and rely on NaN-native
          splits.
        * ASYMMETRIC — LR sees vital-stripped columns (identical to
          DROP's LR matrix). Trees see vitals with NaN-native
          handling (identical to INDICATOR's tree matrix).
      Landed so far:
        * `VitalsStrategy` enum + `VITAL_COLUMNS` constant live in
          scripts/shared/utils.py.
        * `GradientBoostingClassifier` swapped for
          `HistGradientBoostingClassifier` across classical_ml.py;
          its `HYPERPARAMETERS` grid is rewritten to HistGB's API
          (`learning_rate` / `max_iter` / `max_leaf_nodes` /
          `l2_regularization`).
        * `load_data_set` carries `vitals_strategy: Optional[VitalsStrategy]
          = None`. The DROP arm strips VITAL_COLUMNS at parquet-load

          ignores the parameter. `main()` still calls
          `load_data_set` without the third argument — strategy
          plumbing into the main loop is the next piece.
