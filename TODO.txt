- NARRATIVE SET-ORDER NONDETERMINISM FIXED at three render
  sites in scripts/data_loading/deterministic_narrative.py.
  Three bundle values are typed `set[str]`
  (medication_burden.active_meds returned by polypharmacy(),
  medication_burden.nsaid_ingredients returned by

  with each other (they all use deepcopy'd bundles) but
  disagreed with baseline (which uses the ORIGINAL bundle).
  This silently inflated the byte-diff hit rate for every
  spec by adding reorder-noise on top of the genuine swap
  signal. Fix: wrap each iterable inside the f-string with
  sorted(...). Lines 229, 236, 237. Sets are tiny (single-
  digit counts); sort cost is irrelevant. Fix landed at
  render time NOT at extractor time because the extractors
  are also consumed by feature_vector.py, KNN scoring, and
  classical_ml — changing their return type would ripple.
  Sorting at the render boundary is the minimum-blast-radius
  fix. Post-fix smoke verified byte-equality: baseline +
  swap_race + swap_psych_history + swap_safety + swap_sdoh
  all render the same med-list line for patients whose
  donor's perturbed field happened to match the anchor.

- DONOR-SELECTION STRATEGY UPGRADED from per-anchor seeded random
  draw (which allowed donor REPEATS across the cohort and biased
  the marginal distribution of the perturbed field) to COHORT-
  WIDE PAIRING via Sattolo's algorithm:
    * build_pairings(patient_ids) iterates ABLATIONS; per spec,
      seeds an RNG on (spec_id, SEED) — NOT (anchor_id, spec_id,
      SEED) — and runs Sattolo's algorithm on a copy of the
      cohort ID list. Sattolo (rng.randrange(i), exclusive upper
      bound) guarantees zero fixed points: every patient ends up
      displaced, no anchor is paired with itself, every patient
      is used as a donor exactly once.
    * Returns Dict[str, Dict[str, str]] — outer keyed by spec id,
      inner dict maps anchor_id -> donor_id. ONE derangement per
      spec, used across the entire cohort.
    * Marginal distribution preservation: because every patient
      appears as a donor exactly once per spec, the multiset of
      donor-supplied values for the perturbed field across the
      cohort EXACTLY equals the cohort's original multiset of
      that field, just permuted to different anchors. With-
      replacement sampling cannot guarantee this.

- np.array vs np.ndarray TYPO fixed in
  scripts/digital_twins/predictions/feature_importance.py
  line 116 (parameter annotation) and line 124 (docstring).
  np.array is a callable, NOT a class; the PEP 604 union
  operator (X | Y) forces evaluation and `function | NoneType`
  raises TypeError at import time. Standalone annotations
  (x: np.array, no |) silently store the function as the
  annotation and never crash — the | operator is the only
  thing that exposes the type-vs-callable distinction. Without
  `from __future__ import annotations` (which is absent in this
  file), the crash is unavoidable on the union form.

- ABLATION STRATEGY PIVOT: NEUTRALIZE -> COHORT PERMUTATION.
    * Mentor pushback: writing "Missing" / "Absent" / "0" into a
      populated field plants *false* missing information. The
      embedder may have learned distinct semantics for genuine
      missingness; injecting that token where there was a real
      value confounds the ablation signal with a missingness
      signal we did not intend to measure.
    * NEW STRATEGY: for each anchor patient, replace the perturbed
      field's value with the same field's value drawn from a
      randomly chosen DONOR patient in the cohort. The embedder
      sees a real-looking value; the field's correlation with the
      anchor's outcome is severed; the field's marginal
      distribution is preserved exactly (sampled from the empirical
      marginal, not a synthetic placeholder).
    * Standard permutation-importance trick (Breiman 2001) lifted
      from the feature-vector level to the embedder-input level.
      Conceptually: scramble that one column across patients, then
      re-embed.
    * Section-level ablation: draw ONE donor per anchor and copy
      EVERY field in the section jointly. Preserves intra-section
      coherence so the embedder reads a clinically plausible block,
      not a Frankenstein mosaic. Single-donor-per-section is the
      default. Multi-donor-per-section (each field permuted
      independently) is strictly stronger but breaks intra-section
      structure and may confound the ablation with coherence loss.
      Deferred.
    * Override-spec format updates (registry dict in the future
      ablation module):
        - field-level:   {"field": "<field_name>",
                          "strategy": "permute"}
        - section-level: {"section": "<section_header>",
                          "strategy": "permute_section"}

    * deterministic_narrative chokepoint now needs three new
      inputs: (a) the anchor patient ID, (b) access to the cohort
